# Reviewing the constraint pilot

`vlm-tamp annotate` creates one draft JSON per observation plus `schema.json.schema`. Existing annotation files are preserved. The manifest's joint metadata can assist review; it is evaluator-only kinematic information.

For each reviewed observation, identify task-relevant benchmark entity IDs, exact manipulable parts where supported, required or conditional intermediate goals, dependencies, and manipulation constraints. Stages need stable action labels and explicit entities. Dependencies reference stage IDs. Constraint records specify type/category, entities, stage IDs, scope, requirement, condition, frame assumption, evidence, known versus unresolved parameters, and verification status.

Use alternative plans for genuinely different valid strategies. Label context-dependent steps as conditional with the relevant scene condition. Do not mark a top-down grasp, upright transport, or generic contact avoidance as required simply because it is plausible. BDDL final predicates are insufficient to prove path-level requirements. A joint axis/type establishes articulation kinematics, not a complete manipulation strategy.

Set coverage separately for stages, dependencies and constraints. Set `*_complete` only when the annotation explicitly covers alternatives and unnecessary additions well enough to judge precision. `constraint_categories` can restrict evaluation to categories actually reviewed. Provide evidence and reviewer information for every provenance entry; human annotations and simulator/derived-rule references are distinguished. Set `status` to `reviewed` only after review. Annotating a reference does not turn model predictions into verified constraints.

In reference stages/constraints, entity strings are benchmark identifiers; in predictions, entity strings are local IDs linked by resolved entity references. For numerical axes, specify the same frame used by the compared model parameter or an explicitly transformed verified reference. The `axis_sign_invariant` flag describes whether ±axis represents the same constraint. Do not compare world, camera and object-local vectors directly.

Drafts in `annotations/pilot/` intentionally contain coverage gaps and no fabricated stage/path labels. Current whole-object segmentation does not supply drawer-part masks. The next review should include the middle-drawer prismatic joint, the combined drawer-opening/insertion task, and the multiple-bowl spatial tasks. Remaining gaps include grasp/contact requirements, drawer-access conditions, part localization and valid alternative plans.

`review-set` now prepares evidence-backed drafts. `annotations/constraint-review/review.html` includes four observations, original RGB, measured object/independently verified drawer-body overlays, source hashes, published goals and editable conditional stage/contact proposals. Axis values come only from checked simulator references and do not make proposed task constraints verified. Saved drafts have disabled coverage and no human reviewer.

The local interface requires a reviewer name, reviewed-track choices and confirmation to export reviewed JSON. Completeness is separate and defaults to false. Edit/remove unsupported proposals, add valid alternatives, restrict constraint-category coverage where needed and retain remaining gaps. Downloads do not overwrite repository drafts. Place approved files in a separate directory and run `vlm-tamp validate-annotations --annotations PATH` before evaluation. Interface tests are not human reviews; current human-reviewed coverage remains zero.
